## 🚀 &nbsp;Featured Projects

### 🔷 System Monitoring Platform &nbsp; [![GitHub](https://img.shields.io/badge/GitHub-View_Repo-181717?style=flat-square&logo=github)](https://github.com/AhmedRagabMogoda/System-Monitoring)

</div>

> Enterprise-grade **reactive microservices** platform — 5 fully independent services communicating through Kafka event pipelines, with no direct coupling between them.

| What it does | How it does it |
|---|---|
| Ingests system metrics from clients via REST | `Ingestion Service` — validates, normalises, publishes to Kafka |
| Processes metrics asynchronously | `Processing & Alert Service` — consumes Kafka, persists to PostgreSQL |
| Streams live updates to dashboards | `Streaming Service` — Server-Sent Events (SSE) over reactive WebFlux |
| Sends alerts to Slack, Email, Webhooks | `Notification Service` — Resilience4j circuit breakers on all external calls |
| Shared models across services | `Common Library` — multi-module Maven structure |

**Key engineering decisions:** Resilience4j circuit breakers ensure the system degrades gracefully under partial failure. Redis caches high-read endpoints. Flyway enforces versioned schema migrations from day one.

`Spring Boot` · `Spring WebFlux` · `Apache Kafka` · `PostgreSQL` · `Redis` · `Resilience4j` · `Docker` · `Flyway` · `SSE`

### 🟢 Secure Funds Transfer &nbsp; [![GitHub](https://img.shields.io/badge/GitHub-View_Repo-181717?style=flat-square&logo=github)](https://github.com/AhmedRagabMogoda/secure-funds-transfer) &nbsp; [![Live](https://img.shields.io/badge/%E2%96%B6%20Live_Demo-Railway-success?style=flat-square&logo=railway)](https://secure-funds-transfer-production.up.railway.app)

</div>

> **Full-stack financial application** deployed end-to-end on Railway — Spring Boot 3.2 backend + Angular 17 frontend, served from a single multi-stage Docker container.

| What it does | How it does it |
|---|---|
| Secure login + session management | JWT access token (15 min) + refresh token (7 days) |
| Fund transfers between accounts | `@Transactional` — atomic debit + credit + record, or full rollback |
| Sender identity protection | Always derived from JWT principal — never from the request body |
| Transparent token renewal | Angular `BehaviorSubject` gate — one refresh call, all concurrent requests queue and retry |
| Paginated transaction history | 3 dedicated JPQL endpoints: all / sent / received |
| SPA routing in production | `SpaController` + `PathRequest.toStaticResources()` fix for hashed Angular filenames |

**Key engineering decisions:** The multi-stage Dockerfile compiles Angular, embeds the build into Spring Boot static resources, and produces a single deployable JAR — no separate frontend server needed.

`Spring Boot 3.2` · `Angular 17` · `TypeScript` · `RxJS` · `Angular Material` · `PostgreSQL` · `JWT` · `BCrypt` · `Flyway` · `Docker` · `Nginx` · `Railway`
